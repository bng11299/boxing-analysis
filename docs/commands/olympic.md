# Commands: Olympic Boxing: tracking, linking, completeness, frame skips

Moved verbatim from the project rules' `## Commands` on 2026-10-22. Add new recipes here, not to the project rules.

Olympic Boxing: `python olympic_audit.py --data data/olympic` (strict CVAT loader; never publish anything derived) · Tests: `python tests/test_olympic.py`

Two-boxer pose: `python run_ingest.py --track --video <clip> --weights ... --weights-sha256 ... --device cuda:0` (every person with a ByteTrack id -> `<clip>.tracks.npz`; one video per run, tracker state persists) · Credit Olympic punches: `python olympic_attribute.py --data data/olympic --tracks <dir>` · Tests: `python tests/test_tracks.py`

Link ids into two boxers: `python olympic_link.py --data data/olympic --tracks results/ingest/olympic [--reacquire] [--only GH078416 ...]` (-> `results/olympic_linking.json`; `--overlay [GH078416]` renders `<tracks>/<id>.linked.overlay.mp4`, boxer A green / B magenta / others grey, to check identity swaps by eye; `--reacquire` links across gaps up to 60 s, identities then only reliable between re-acquisitions) · Were all punches labelled?: `python olympic_completeness.py --data data/olympic --tracks results/ingest/olympic [--reacquire]` (each wrist-speed burst is matched one-to-one to a label, the boxer's own first then the unattributed ones, optimal within each phase, not necessarily the global maximum of explained bursts, exact ties to the burst that sorts first (frame, boxer); the burst rates and the exposure-qualified own-label rate divide by the boxer's exposure, the frames the rule actually ran on; labels per video boxer-minute is a whole-video density, a different population; the rest are "unexplained" = candidates for missed labels, neither an upper nor a lower bound on unlabelled punches until you classify a sample; -> `results/olympic_completeness.json` and a seeded 40-burst simple random sample `results/olympic_completeness_sample.csv` with its `inclusion_prob`, for YOU to classify; it judges nothing) · Completeness without linking (ADR-0012 Option 2): `python olympic_completeness.py --data data/olympic --tracks results/ingest/olympic --credited [--min-punches N]` (tests only the track ids credited with at least N labelled punches, each one person for its whole length, so no identity is needed; a label is owned by the fragment it is credited to, same matching, exposure and rates; STATED LIMITS: it sees only credited fragments (coverage can only lose), while two overlapping ids on one person can DUPLICATE a punch, so neither a bout-level upper nor a lower bound follows without de-duplication; `possible_duplicates` counts the likely twins (IoU >= 0.3 within 0.1 s) and never subtracts them; a clean result is weak evidence; the attributions are verified against the pose table; the one-punch fragments are the least certain; refuses `--reacquire`; -> `results/olympic_completeness_credited.json` and `..._credited_sample.csv`, whose rows also give `track_id`, the box centre and height in pixels and `m:ss.s` to find the person) · Tests: `python tests/test_completeness_credited.py` · A tracks file is bound to its video by file name, and by content fingerprint when `run_ingest.py` wrote one (older tables: name only, reported `video_bound: false`) · Tests: `python tests/test_linking.py` · Camera frame drops (the GoPro drops captured frames while the timestamps stay regular, and the wrist-speed rule reads the on-screen jump as a fast punch): `python olympic_framechange.py --data data/olympic --tracks results/ingest/olympic [--only GH069681 ...] [--overwrite]` (decodes each video once, one number per frame -> `<tracks>/<id>.framechange.npz`, bound to the video by name, length and content fingerprint; a skip is a frame whose change exceeds 3x the median of its +-10 neighbours, a rule and constant from one observation on one development video, NOT tuned to any score) then `python olympic_completeness.py ... [--credited] --skips` (MASKS the frames within reach of each skip: signal 0 over smooth_window // 2 + 1 frames (3 at 50 fps), exposure removed over one more; segments untouched; reports bursts within 2 frames of a skip against the base rate; writes `..._skips.json` / `..._skips_sample.csv`, never the files of a run without skips; refuses the whole run on a missing or mismatched framechange file) or `--skips-measure` (same report, no mask; both write `skip_bins`, the unexplained and explained bursts per 1,000 exposure frames by distance to the nearest skip with the gate verdict, from `completeness.distance_bins`) · `--skipcheck SAMPLE.csv --skipcheck-out OUT.csv` reads an earlier sample and says which of its bursts are still unexplained with skips · Tests: `python tests/test_frame_skips.py`

Kit colour per track id: `python olympic_colour.py --data data/olympic --tracks results/ingest/olympic [--split dev|test|all] [--only ID ...] [--check-only]` (red / blue / none / unsure from the TORSO's pixels: dark navy counts as blue, the skin band is excluded, the decision is a relative kit index; numbers only, never a crop or image -> `<tracks>/<id>.colours.json`; then the non-circular self-check: co-present credited fragments should get OPPOSITE colours -> `results/olympic_colour_check_v2.<split>.json`; the default `--split dev` reads only the 4 development videos, `--split test` the 25 held-out ones, and the gate (opposite >= 90% AND >= 100 decided pairs, exit 2 below) is evaluated on the test videos only; version 1 stopped at 29.1%; version 2 FAILED the test gate at 52.2% over 582 decided pairs (chance level), so colour is not used for linking; see docs/quality-loop.md) · Tests: `python tests/test_appearance.py`

Headgear corner colour (kit colour v3, gate `docs/gates/appearance-identity.md`): `python olympic_headgear.py --data data/olympic --tracks results/ingest/olympic --counts-dir results/headgear [--split dev|heldout|all] [--only ID ...] [--check-only]` (crown of the headgear, read on the frames two credited people share; dev by default; `heldout` = 23 videos, G1 needs >= 90% opposite over >= 100 decided pairs and a video-bootstrap lower bound >= 0.80; counts only, never pixels; exit 2 = gate fails) · Tests: `python tests/test_headgear.py`

Ring-floor filter (gate `docs/gates/ring-floor-filter.md`; drops tracked people whose feet stand outside the ring floor, whole ids only, then links and tests completeness exactly as above): `python olympic_ring.py prepare --data data/olympic` (per video a person-free background image and the camera's motion from its starting position, pixels only -> `results/olympic_ring/`; a camera that moves more than 20 px is left out of both arms) -> `python olympic_ring.py click --floors <floors.json>` (a person clicks each ring floor on its background, timed, development videos first; keep the file in a gitignored `data/` folder) -> `python olympic_ring.py evaluate --data data/olympic --tracks results/ingest/olympic --floors <floors.json> --rule results/punch_finder_v6.json --split dev` (the margin grid on ADR-0013's 4 development videos and the margin the gate's rule picks) -> `... --split heldout` (the verdict; refused until `FROZEN_MARGIN_PX` is committed; exit 2 = gate fails; `--write-filtered DIR` also writes the filtered tables for the CLIs above and overlays) · Tests: `python tests/test_ring.py`
